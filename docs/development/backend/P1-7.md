## 1. 三个具体障碍与解法

| 障碍 | 解法 |
| --- | --- |
| 同步 action 返回 `Message`，网络是异步 | **乐观 commit**：内存 `snapshot` 立即更新、action 签名与返回值一字不改；持久化走后台队列（`void`），失败进重试队列，用现有 `status` block 显示，不新增 UI |
| `appendDelta` 每 chunk 都 commit | 流式中间态**不落库**；只在 `finishAssistantMessage` 后按会话触发一次同步，节流 300ms |
| 服务端表装不下 context / blocks / meta / error | 扩列（见 §2），`dock` / `activeId` 留本地 —— 它们是 UI 表现，跨设备不需要 |

## 3. API 与落盘

新增 `chat` surface（2 个端点，按 `OVERVIEW.md:33` 够格建 `routes/` 模块），**共用 P1-3 的两张表**，不改 `/api/conversations`。

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `GET` | `/api/chat/state` | 返回 `ChatStateDto`（conversations 全量 + version），按成员工作区过滤 |
| `PUT` | `/api/chat/state` | 全量保存，带 `expectedVersion`；409 表示服务端更新过，重新拉再合并 |

| 文件 | 职责 |
| --- | --- |
| `src/lib/chat.ts` | 唯一契约：`ChatBlock` / `ChatMessageDto` / `ChatConversationDto` / `ChatStateDto`、`CHAT_STATE_PATH`、校验与错误形状 |
| `server/routes/chat.ts` | GET / PUT，401 → 403 → 写，事务 upsert 两表，版本冲突 409 |
| `server/router.ts` | 加 `/api/chat*` 分发 |
| `src/services/chat/client.ts` | `getState()` / `putState()`，`credentials: 'include'`，失败不抛、返回 `ConversationErr` 风格 |
| `src/state/chat.ts` | 双模式、乐观 commit、节流持久化、旧 envelope 导入；**对外 API 全部不变** |

**双模式**：`VITE_CHAT_SOURCE=local|api`，默认 `local`。`local` 走原 `commit()` 路径，逐字节不变；`api` 才启用后台队列。`VITE_` 前缀会进浏览器 bundle，但它只是模式开关、不是密钥，`.env.example` 要写明。
